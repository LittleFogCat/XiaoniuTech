# 前端合并重构计划 2025-05-02

## 背景

当前前端分为两套：

1. `frontend/`
   - 纯静态主页
   - 入口是 `frontend/index.html`
   - 依赖静态 `css/`、`image/`、少量内联脚本

2. `frontend/`
   - 独立的 React + Vite 项目
   - 通过 `npm run build` 生成 `dist`
   - 当前生产 `base` 为 `/chat/`

这导致部署时需要分别处理主页和聊天页，至少包含以下额外成本：

- 主页与聊天需要分别维护构建/发布路径
- Nginx 静态目录需要人工协调
- 前端路由、资源路径、站点入口分裂
- 后续要做统一登录、统一导航、统一样式体系时成本更高

## 本次重构目标

将主页与 chat 合并为同一个前端项目，最终达到：

- 只保留一套前端工程
- 只执行一次构建
- 只部署一份 `dist`
- 首页路径保持为 `/`
- 聊天路径保持为 `/chat`
- 后续扩展博客、小游戏、用户中心时继续沿用同一工程

## 方案选择

### 推荐方案

以 `frontend/` 作为唯一保留的前端工程，把当前静态主页迁移进 React + Vite 项目。

### 选择理由

- 现有 chat 已经具备完整的构建链路
- 已有 API 调用、状态管理、组件结构，不适合反向迁移回纯静态站点
- 首页迁移进 React 的成本明显低于把 chat 拆回静态页面
- 后续增加路由、统一布局、统一鉴权更自然

## 重构后的目标结构（建议）

```text
frontend/
├── public/
│   ├── image/
│   └── ...
├── src/
│   ├── components/
│   ├── pages/
│   │   ├── HomePage.jsx
│   │   └── ChatPage.jsx
│   ├── layouts/
│   ├── services/
│   ├── App.jsx
│   ├── main.jsx
│   └── index.css
└── package.json
```

说明：

- `frontend/` 原静态资源逐步迁入 `frontend/public/` 或 `frontend/src/`
- 首页内容重写为 React 页面组件 `HomePage.jsx`
- 现有聊天页逻辑收敛为 `ChatPage.jsx` 或保留原 `App.jsx` 后再拆分
- 最终部署产物统一为一个 `dist/`

## 关键技术决策

### 1. 路由方案

建议新增前端路由：

- `/` -> 首页
- `/chat` -> 聊天页

这样可以保留现有 URL 语义，不需要用户改变访问习惯。

### 2. Vite base 策略

当前 chat 生产 `base` 为 `/chat/`，这不适合“首页 + chat”同构建产物的场景。

重构后建议：

- 将 `base` 调整为 `/`
- 资源以根路径发布
- Nginx 对前端路由做 SPA fallback

### 3. 资源迁移策略

主页里的静态资源按两类迁移：

1. 不参与打包计算、仅作为静态文件提供：
   - 放入 `public/`

2. 需要模块化引用、后续可能组件化管理：
   - 放入 `src/assets/`

建议首轮迁移以稳定为先，优先放到 `public/`，等结构稳定后再继续组件化。

### 4. 首页迁移策略

不要继续保留一份额外静态 `index.html`。

建议直接把首页内容迁成 React 页面，而不是试图在构建后把一份静态 HTML 再拼回 `dist`。后者会继续保留双入口和双维护成本，达不到本次重构目标。

## 风险点

### 1. `/chat/` -> `/chat` 的路径与资源回归

当前构建基路径带 `/chat/`。改成单项目后，可能影响：

- 首页跳转链接
- 构建资源引用路径
- Nginx 路由转发
- 刷新 `/chat` 时的 404 行为

### 2. 主页样式迁移成本

静态主页目前依赖手写 CSS 和 DOM 结构，迁入 React 后可能出现：

- 样式丢失
- 交互细节变化
- 响应式表现不一致

### 3. 聊天页状态与路由耦合

登录态、游客模式、当前会话、注册流程等都已在 chat 中落地。改造时需要避免：

- 路由切换导致状态重置
- 首页与聊天页来回切换引发重复请求
- 登录后跳转路径不正确

## 建议实施顺序

1. 先在 `frontend` 中接入路由，但不动首页样式
2. 把现有聊天页包进 `/chat` 页面，先保证聊天功能不回归
3. 新增一个最小可用版首页 React 页面，先打通统一构建
4. 再把原静态首页逐步迁进 React 组件与样式
5. 最后统一调整 Nginx、部署说明、目录清理
