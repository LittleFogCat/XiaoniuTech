# 定义

定义服务器中的项目根目录为 `{project}`。

# 快速部署说明（概览）

本项目使用 Docker Compose 管理以下服务：
- Nginx（用于托管前端静态文件和反向代理）
- MongoDB（数据存储）
- Backend（Express + Node.js API）

下文给出推荐的步骤与注意事项，分为前端、后端、Nginx、以及运行与更新策略。

## 前置要求

- 在服务器上安装 Docker 和 Docker Compose（或使用 Docker Engine + Compose 插件）。例如基于 Debian/Ubuntu：

```bash
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io
apt-get install -y docker-compose-plugin
```

- 确保有权限创建网络与卷，且目标端口（80/443/3001 等）未被占用。

## 前端部署（生产）

1. 在本地或 CI 中构建前端：

```bash
cd frontend/chat
npm install
npm run build
```

2. 构建产物位于 `frontend/chat/dist`，将其上传或复制到服务器上的 `{project}/www/chat/`（或将 `frontend/chat/dist` 挂载到 Nginx 对应目录）。

> 注意：`docker-compose.yml` 配置中将 `./frontend/chat/dist` 挂载到 Nginx 下的 `/usr/share/nginx/html/chat`，部署时需保证该路径存在且含有构建好的文件。

## 后端部署

1. 将 `backend` 目录的源码（或构建产物）放到服务器合适位置（示例：`{project}/data/backend/`）。

2. 当前 `docker-compose.yml` 中 `backend` 服务使用 `build:`（从 `./backend/Dockerfile` 构建镜像）。因此：

	- 如果你上传了新的后端源码，必须重新构建镜像并重启服务：

```bash
docker-compose build backend
docker-compose up -d backend
```

	- 开发时可使用 bind-mount（将宿主 `./backend` 挂载到容器）并运行 nodemon 实现热重载，请使用专用 `docker-compose.dev.yml` 或 `Dockerfile.dev`，不要在生产使用热重载。

## MongoDB 与数据卷

- `docker-compose.yml` 使用名为 `mongo-data` 的卷保存数据。该卷一旦初始化，`MONGO_INITDB_ROOT_PASSWORD` 只在首次初始化时生效。若需更改 root 密码：

	- 在容器内用旧密码登录并修改密码（不丢失数据）：

	```bash
	docker-compose exec mongodb mongosh -u root -p 'OLD_PW' --eval "db.getSiblingDB('admin').changeUserPassword('root','NEW_PW')"
	```

	- 或在可以接受丢失数据的情况下删除卷并重建：

	```bash
	docker-compose down -v
	docker-compose up -d
	```

## Nginx 部署

1. 将 `conf/nginx/` 内容上传到 `{project}/conf/nginx/`，Compose 配置会把该目录挂载到容器内的 `/etc/nginx`。

2. 确保 Nginx 的站点配置指向正确的前端目录和代理后端（如 `http://backend:3001`）。

## 模型配置

将模型配置信息保存在 `{project}/conf/backend/models.json` 文件中。

## 启动与重启

- 初次启动（在 `{project}` 目录下）：

```bash
docker-compose up -d --build
```

- 仅重建并重启 `backend`：

```bash
docker-compose build backend
docker-compose up -d backend
```

- 检查服务状态与日志：

```bash
docker-compose ps
docker-compose logs -f backend
docker-compose logs -f mongodb
```

## 更新代码（注意点）

- **生产**：建议通过 CI 构建镜像并推送到私有/公有镜像仓库，服务器通过 `docker-compose pull` 与 `docker-compose up -d` 更新容器；不要在生产使用宿主源码 bind-mount。 
- **开发**：可使用 `docker-compose.dev.yml`（示例：挂载 `./backend` 到容器并运行 `npm run dev`），实现热重载，避免每次代码更改都重建镜像。

## 常见问题与排查

- 查看 Compose 最终解析：

```bash
docker-compose config
```

- 若 MongoDB 无法启动，检查卷与权限，查看日志：

```bash
docker-compose logs -f mongodb
```

- 若 Nginx 未加载新前端页面，确认 `frontend/chat/dist` 是否被正确复制到挂载目录并检查 Nginx 配置。
