# 目录结构说明

本文说明仓库源码结构、打包产物结构，以及服务器上的目标部署目录结构。

## 源码仓库结构

```text
backend/                 后端源码
frontend/                前端源码（Vite）
conf/                    部署配置与运行时种子配置
  backend/               后端运行配置（models.json、backend.conf、identities/）
  compose/               源码中的 Compose 文件
  nginx/                 Nginx 配置
script/                  打包与部署脚本
  build.bat              Windows 打包入口
  build.ps1              Windows 打包实现
  install.sh             服务器端部署脚本
doc/                     文档
tmp/                     临时任务和本地打包输出
```

## 本地打包输出结构

执行 `script/build.bat` 后，默认输出到 `tmp/build/`：

```text
tmp/build/
  build.tar.gz
  target/                仅在传入 --keeptmpfile 时保留
    backend/
    frontend/
    conf/
    install.sh
```

其中：

- `backend/`：从源码仓库中的 `backend/` 复制而来，并排除了 `backend/.gitignore` 中声明的内容。
- `frontend/`：来自 `frontend/dist/` 的构建产物。
- `conf/`：来自源码仓库中的 `conf/`。
- `install.sh`：服务器端部署脚本副本。

## 服务器部署目录结构

假设服务器项目根目录为 `{project}`，使用 `install.sh` 部署后，目录结构如下：

```text
{project}/
  docker-compose.yml     由 conf/compose/docker-compose.yml 复制而来
  bak/                   自动备份目录
  conf/
    nginx/
    backend/
  data/
    backend/
  www/
```

其中：

- `{project}/data/backend/`：部署后的后端源码，用于构建 backend 镜像。
- `{project}/www/`：部署后的前端静态文件。
- `{project}/conf/nginx/`：Nginx 配置。
- `{project}/conf/backend/`：后端运行配置与 identity 种子配置。
- `{project}/bak/`：每次部署前自动生成的备份压缩包。

## 备份文件命名

部署脚本会按时间戳生成备份压缩包：

- `data.bak.{datetime}.zip`
- `www.bak.{datetime}.zip`
- `conf.bak.{datetime}.zip`

这些文件统一存放在 `{project}/bak/`。
